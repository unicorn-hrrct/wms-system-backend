## 一、通用约定

### 1.1 基础信息

- 接口前缀：`/api`
- 数据格式：JSON（`Content-Type: application/json`）
- 鉴权方式：（如 Header 携带 `Authorization: Bearer <token>`）

### 1.2 统一响应格式

```json
{
  "code": 0,        // 0 成功，非 0 失败
  "message": "ok",  // 提示信息
  "data": {}        // 业务数据，失败时可为 null
}
```

### 1.3 通用错误码

| code | 含义 |
|------|------|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 1.4 分页约定

请求参数：`page`（从 1 开始）、`pageSize`（默认 10）
响应 data 结构：`{ "list": [], "total": 0, "page": 1, "pageSize": 10 }`

## 三、接口详细定义

> 每个接口按以下格式编写。

### A01 用户注册

- **路径**：`POST /api/auth/register`
- **请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 4~20 位字母数字 |
| password | string | 是 | 6~20 位 |
| phone | string | 否 | 手机号 |

- **成功响应示例**：

```json
{ "code": 0, "message": "ok", "data": { "id": 1, "username": "zhangsan" } }
```

- **失败情形**：用户名已存在（code=400，message="用户名已存在"）
