# 验收标准

> 验收时间：第 4 周最后两天，现场演示 + 答辩。

## 一、验收流程

1. **系统演示**（15 分钟）：按验收清单逐项演示，教师现场操作抽查。
2. **答辩问答**（15 分钟）：每位成员按模块答辩——
   - 讲解并抽问自己负责模块的实现细节（库表、接口、页面全链路）；
   - 交叉抽问 1 个其他成员模块的基础问题（考察协作与整体理解）。
3. **材料检查**：检查仓库文档完整性、Git 提交记录（与模块分工比对）、日报周报、交叉 Code Review 记录。

## 三、非功能验收项

| 编号 | 验收项 | 标准 |
|------|--------|------|
| N01 | 部署 | 系统部署在服务器上，通过浏览器可正常访问 |
| N02 | 稳定性 | 演示全程无崩溃、无白屏、无未处理异常 |
| N03 | 数据 | 预置不少于 30 个商品、3 个以上分类的演示数据 |
| N04 | 安全 | 密码加密存储；未登录不能访问需登录的页面/接口 |
| N05 | 兼容 | Chrome/Edge 最新版正常显示，无明显样式错乱 |

## 四、材料验收项

| 编号 | 验收项 | 标准 |
|------|--------|------|
| D01 | 文档完整 | docs 下各阶段文档齐全且按模板填写 |
| D02 | 日报 | 每人每个工作日一份，无批量补写痕迹 |
| D03 | 周报 | 每周一份，内容与实际进度一致 |
| D04 | Git 记录 | 每人有持续提交记录，提交信息规范，提交内容与所负责模块一致 |
| D05 | 分工执行 | 按模块负责制分工，有交叉 Code Review 记录 |

## 五、验收结论

- **通过**：必做功能 F01~F13 全部通过，选做 ≥ 2 项、挑战模块 ≥ 1 项通过，非功能项与材料项无严重缺失。
- **有条件通过**：必做功能不通过项 ≤ 2 项，或挑战模块未通过但有明确整改方案，限 3 天内整改后复验。
- **不通过**：必做功能不通过项 ≥ 3 项，或存在抄袭。
