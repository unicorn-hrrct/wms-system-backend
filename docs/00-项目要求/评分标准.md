# 评分标准

> 总分 100 分 = 小组得分（70%） + 个人得分（30%）

## 一、小组得分（100 分制，占总评 70%）

| 维度 | 分值 | 评分要点 |
|------|------|----------|
| 功能实现 | 40 | 必做功能 28 分（按验收清单通过项计分）；选做功能 4 分（≥2 项）；挑战模块 8 分（≥1 项，含边界演示/压测证明） |
| 系统设计 | 15 | 架构合理、数据库设计规范（三范式/合理冗余）、接口设计统一 |
| 代码质量 | 15 | 命名规范、结构清晰、无大量重复代码、有基本错误处理 |
| 文档质量 | 10 | 各阶段文档齐全、按模板、内容与实现一致 |
| 测试与部署 | 10 | 有测试计划与报告、缺陷有记录有闭环、成功部署 |
| 过程管理 | 10 | 周报质量、进度控制、会议记录、任务分配合理 |

## 二、个人得分（100 分制，占总评 30%）

| 维度 | 分值 | 评分要点 |
|------|------|----------|
| 模块完成度与工作量 | 40 | 所负责模块（库表+接口+页面全链路）的完成度 × 模块难度权重；Git 提交记录数量与质量 |
| 日报质量 | 20 | 按时提交、内容真实具体、问题与思考有深度 |
| 答辩表现 | 30 | 本模块讲解与抽问 20 分 + 交叉抽问（其他成员模块基础问题）10 分 |
| 团队协作 | 10 | 交叉 Code Review 参与度、组长评价 + 组内互评 |

> 模块难度权重见《项目要求》3.2 节。模块由他人代写（Git 记录与分工不符）者，模块完成度分按情节扣减直至 0 分。

## 三、加分项（总评最多加 5 分）

- 完成第 2 个及以上挑战模块，且通过边界演示/压测验收（每个 +2）
- 使用 CI/CD 自动化部署（+2）
- 单元测试覆盖核心业务逻辑（+2）
- 界面设计优秀、体验流畅（+1~2）

## 四、扣分与一票否决

| 情形 | 处理 |
|------|------|
| 文档/日报明显批量补写、内容雷同 | 相关项 0 分 |
| 无法讲清自己模块的代码 | 个人答辩分减半 |
| 按前后端横向分工、未执行模块负责制 | 小组过程管理分 0 分，个人模块完成度分按实际认定 |
| 抄袭其他组代码或文档 | 相关组总评 0 分 |
| 演示系统非本仓库代码构建 | 小组功能分 0 分 |

## 五、成绩等级

| 总评 | 等级 |
|------|------|
| 90~100 | 优秀 |
| 80~89 | 良好 |
| 70~79 | 中等 |
| 60~69 | 及格 |
| <60 | 不及格 |
