### 9.1 Redis 分布式锁防超卖（13.1）

#### 9.1.1 安全扣减库存

```
Client → POST /api/advanced/stock/lock/decrease {skuId, quantity, orderId, expireSeconds:900}
       → StockLockService
       │
       ├─ ① Redis EVAL stock_decrease.lua
       │    KEYS = [stockKey="stock:{skuId}", lockKey="lock:order:{orderId}"]
       │    ARGV = [quantity, orderId, ttl]
       │
       │    -- Lua 脚本（原子执行）
       │    local cur = tonumber(redis.call('GET', KEYS[1]) or '0')
       │    if cur < quantity then return {0, cur} end
       │    redis.call('DECRBY', KEYS[1], quantity)
       │    redis.call('HSET', KEYS[2], 'qty', quantity, 'skuId', skuId)
       │    redis.call('EXPIRE', KEYS[2], ARGV[3])
       │    return {1, cur - quantity}
       │
       ├─ ② 若返回 {0, cur} → 抛 BusinessException("库存不足，当前可用库存："+cur) → 50001
       ├─ ③ 若返回 {1, remain} → 写库（DB 层再次校验）：
       │    UPDATE sto_stock SET quantity=quantity-?, locked_quantity=locked_quantity+?
       │    WHERE sku_id=? AND (quantity-locked_quantity) >= ?
       │    影响行数=0 → 释放 Redis 锁、回滚
       ├─ ④ 写 sto_stock_log
       └─ ⑤ 返回 {lockId, skuId, lockedQuantity, remainingStock, expireAt}
```

**为什么需要 DB 二次校验**：
- Redis 是缓存，可能丢失；DB 是真值
- Redis Lua 已保证**当前不会超卖**，但如果 Redis 宕机重启，DB 仍能兜底
- 同时防止 Redis 缓存与 DB 不一致（缓存穿透/击穿）

---

#### 9.1.2 释放 / 确认库存锁

```
Client → POST /api/advanced/stock/lock/release {lockId, action:confirm|cancel}
       → StockLockService
       │
       ├─ action=confirm（支付成功）：
       │    ├─ DB：UPDATE sto_stock SET locked_quantity = locked_quantity - ? WHERE sku_id=?
       │    ├─ Redis：DEL stock:{skuId} 对应 lockKey 中的 qty（库存总量不再回滚，已是真扣）
       │    └─ 不写库存流水（已 write 过）
       │
       └─ action=cancel（订单取消）：
            ├─ DB：UPDATE sto_stock SET quantity = quantity + ?, locked_quantity = locked_quantity - ?
            ├─ Redis：INCRBY stock:{skuId} quantity
            ├─ INSERT sto_stock_log（quantity_change=+n, remark=订单取消回滚）
            └─ DEL lockKey
```

**过期自动释放**：Redis `EXPIRE 900` 到期后自动过期；后台扫表 `sto_stock` 若发现 `locked_quantity>0` 但关联订单已取消/超时，自动补偿。

- 失败重试：3次指数退避，仍失败入死信队列

### 9.6 智能补货（13.6）

```
定时任务 @Scheduled(cron="0 0 2 * * ?")  每日凌晨 2 点
       │
       ▼
RestockService.generateSuggestions()
       │
       ├─ ① 加载规则：defaultSafetyStockDays=7, leadTime=3, salesHistoryDays=30
       ├─ ② 算日均销量：
       │    SELECT sku_id, SUM(quantity)::numeric / 30 AS avg_daily
       │    FROM ord_order_item oi JOIN ord_order o ON oi.order_id=o.id
       │    WHERE o.pay_time >= NOW() - INTERVAL '30 day' AND o.status IN (1,2,3)
       │    GROUP BY sku_id
       ├─ ③ 算当前库存：SELECT sku_id, SUM(quantity) FROM sto_stock GROUP BY sku_id
       ├─ ④ 对每个 SKU：
       │    daysRemaining = currentStock / avgDailySales
       │    safetyStock = avgDaily * safetyStockDays
       │    suggestedQty = (safetyStock + avgDaily * leadTime) - currentStock
       │    urgency =
       │      daysRemaining < 3           → "HIGH"
       │      daysRemaining < safetyDays  → "MEDIUM"
       │      else                        → "LOW"
       │    INSERT res_restock_suggestion
       └─ ⑤ 发 stock.alert MQ 通知

Client → POST /api/advanced/restock/generate-order {suggestionIds[], autoMerge:true}
       → RestockService
       ├─ ① 加载 suggestions
       ├─ ② 按 supplierId 分组（autoMerge=true）
       ├─ ③ 对每个 supplier 生成 pur_request（status=0）
       └─ ④ 返回 {generatedOrders:[...]}
```

### 9.8 Redis Lua 脚本全集

> **3 个 Lua 脚本对应 3 个操作**，全部放在 `resources/lua/` 目录下，启动时 `SCRIPT LOAD` 预加载，避免每次 EVAL 重新编译。

#### 9.8.1 stock_decrease.lua（扣减）

```lua
-- KEYS[1] = stockKey (e.g. "stock:2001")
-- KEYS[2] = lockKey  (e.g. "lock:order:9001")
-- ARGV[1] = quantity
-- ARGV[2] = skuId
-- ARGV[3] = orderId
-- ARGV[4] = ttl (seconds)

local stockKey = KEYS[1]
local lockKey  = KEYS[2]
local quantity = tonumber(ARGV[1])
local skuId    = ARGV[2]
local orderId  = ARGV[3]
local ttl      = tonumber(ARGV[4])

-- 1. 读当前库存
local current = tonumber(redis.call('GET', stockKey) or '0')

-- 2. 库存不足，返回 {0, current}
if current < quantity then
    return {0, current}
end

-- 3. 扣减
redis.call('DECRBY', stockKey, quantity)

-- 4. 记录锁信息（用于 confirm/cancel 时识别）
redis.call('HSET', lockKey,
    'skuId', skuId,
    'orderId', orderId,
    'quantity', quantity,
    'originalStock', current,
    'createTime', redis.call('TIME')[1]
)

-- 5. 设置过期时间（防死锁）
redis.call('EXPIRE', lockKey, ttl)

-- 6. 返回成功
return {1, current - quantity}
```

#### 9.8.2 stock_confirm.lua（确认扣减=支付成功）

```lua
-- KEYS[1] = lockKey
-- ARGV[1] = action = "confirm"

local lockKey = KEYS[1]
local action  = ARGV[1]

-- 1. 检查锁是否存在
local exists = redis.call('EXISTS', lockKey)
if exists == 0 then
    return {0, 'LOCK_NOT_FOUND'}
end

-- 2. confirm 只删除锁，不回滚 quantity（已真扣）
redis.call('DEL', lockKey)
return {1, 'OK'}
```

#### 9.8.3 stock_cancel.lua（取消=回滚库存）

```lua
-- KEYS[1] = stockKey
-- KEYS[2] = lockKey
-- ARGV[1] = action = "cancel"

local stockKey = KEYS[1]
local lockKey  = KEYS[2]

-- 1. 检查锁
local exists = redis.call('EXISTS', lockKey)
if exists == 0 then
    return {0, 'LOCK_NOT_FOUND'}
end

-- 2. 取出原扣减数量
local qty = tonumber(redis.call('HGET', lockKey, 'quantity') or '0')
if qty == 0 then
    return {0, 'INVALID_QTY'}
end

-- 3. 回滚库存
redis.call('INCRBY', stockKey, qty)

-- 4. 删除锁
redis.call('DEL', lockKey)

return {1, qty}
```

### 9.9 Java 调用 Lua 的 Service 模板

```java
@Service
@RequiredArgsConstructor
public class StockLockServiceImpl implements StockLockService {

    private final StringRedisTemplate redis;
    private final DefaultRedisScript<List> decreaseScript;
    private final DefaultRedisScript<List> confirmScript;
    private final DefaultRedisScript<List> cancelScript;

    /**
     * 启动时加载 Lua 脚本
     */
    @PostConstruct
    public void loadScripts() {
        decreaseScript.setScriptSource(
            new ResourceScriptSource(new ClassPathResource("lua/stock_decrease.lua")));
        decreaseScript.setResultType(List.class);
        // confirmScript / cancelScript 同理
    }

    /**
     * 扣减库存
     */
    @Override
    public LockResult lockDecrease(Long skuId, Integer qty, Long orderId, Integer expireSeconds) {
        String stockKey = "stock:" + skuId;
        String lockKey  = "lock:order:" + orderId;
        String lockId   = "LOCK-" + orderId + "-" + skuId;

        List<Long> result = redis.execute(decreaseScript,
            Arrays.asList(stockKey, lockKey),
            String.valueOf(qty),
            String.valueOf(skuId),
            String.valueOf(orderId),
            String.valueOf(expireSeconds != null ? expireSeconds : 900)
        );

        long code = result.get(0);
        long remain = result.get(1);

        if (code == 0) {
            throw new BusinessException("库存不足，当前可用库存：" + remain, 50001);
        }

        return new LockResult(lockId, skuId, qty, remain,
            LocalDateTime.now().plusSeconds(expireSeconds != null ? expireSeconds : 900));
    }

    /**
     * 释放/确认锁
     */
    @Override
    public void release(Long skuId, Long orderId, String action) {
        String stockKey = "stock:" + skuId;
        String lockKey  = "lock:order:" + orderId;

        DefaultRedisScript<List> script = "confirm".equals(action) ? confirmScript : cancelScript;
        List<Long> result = redis.execute(script,
            Arrays.asList(stockKey, lockKey),
            action);

        if (result.get(0) == 0L) {
            log.warn("释放库存锁失败 skuId={} orderId={} action={} msg={}",
                skuId, orderId, action, result.get(1));
        }
    }
}
```

#### 9.10.4 生产者骨架

```java
@Service
@RequiredArgsConstructor
public class OrderMessageProducer {

    private final LocalMessageMapper localMessageMapper;
    private final RabbitTemplate rabbitTemplate;  // 或 RocketMQTemplate / KafkaTemplate

    /**
     * 业务事务内：插入本地消息（不发）
     */
    @Transactional(propagation = Propagation.MANDATORY)
    public String prepareMessage(String topic, Object payload) {
        String messageId = UUID.randomUUID().toString();
        LocalMessage msg = new LocalMessage();
        msg.setMessageId(messageId);
        msg.setTopic(topic);
        msg.setPayload(JSON.toJSONString(payload));
        msg.setStatus(0);
        localMessageMapper.insert(msg);
        return messageId;
    }

    /**
     * 事务提交后：投递到 MQ
     */
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onCommit(OrderMessageEvent event) {
        try {
            rabbitTemplate.convertAndSend(event.getTopic(), event.getMessageId(), event.getPayload());
            localMessageMapper.markSent(event.getMessageId());
        } catch (Exception e) {
            log.error("MQ 投递失败 messageId={}", event.getMessageId(), e);
            // 不抛异常，让定时任务兜底重投
        }
    }
}
```

#### 9.10.5 消费者骨架（幂等）

```java
@Component
@RequiredArgsConstructor
public class OrderCreatedConsumer {

    private final StockLogMapper stockLogMapper;
    private final ConsumeLogMapper consumeLogMapper;

    @RabbitListener(queues = "order.created.inventory")
    public void onMessage(String messageId, String payload) {
        // 1. 幂等检查
        int inserted = consumeLogMapper.tryInsert(messageId, "inventory");
        if (inserted == 0) {
            log.info("消息已消费过 messageId={}", messageId);
            return;
        }

        try {
            // 2. 业务处理
            OrderMessage msg = JSON.parseObject(payload, OrderMessage.class);
            stockLogMapper.insert(StockLog.builder()
                .skuId(msg.getSkuId())
                .type(2)
                .typeName("订单预扣")
                .quantityChange(-msg.getQuantity())
                .sourceNo(msg.getOrderNo())
                .build());

            // 3. ACK（自动确认模式可省略）

        } catch (Exception e) {
            // 4. 失败删除幂等记录，允许重试
            consumeLogMapper.deleteById(messageId);
            throw new AmqpRejectAndDontRequeueException("处理失败", e);
            // 或根据重试次数决定入死信队列
        }
    }
}
```

#### 9.10.6 失败重试策略

| 重试次数 | 间隔 | 处理 |
|----------|------|------|
| 1 | 立即 | 重新消费 |
| 2 | 5 秒 | 重新消费 |
| 3 | 30 秒 | 重新消费 |
| 4+ | — | 入死信队列（DLQ），人工介入 |

```java
public class JwtHandshakeInterceptor implements HandshakeInterceptor {

    private final JwtUtil jwtUtil;

    @Override
    public boolean beforeHandshake(ServerHttpRequest request,
                                   ServerHttpResponse response,
                                   WebSocketHandler wsHandler,
                                   Map<String, Object> attributes) {
        // 从 URL 拿 token
        String token = null;
        if (request instanceof ServletServerHttpRequest req) {
            token = req.getServletRequest().getParameter("token");
        }
        if (!StringUtils.hasText(token) || !jwtUtil.validateToken(token)) {
            response.setStatusCode(HttpStatus.UNAUTHORIZED);
            return false;
        }

        // 解析 userId 放入 attributes
        Long userId = jwtUtil.getUserIdFromToken(token);
        attributes.put("userId", userId);
        return true;
    }

    @Override
    public void afterHandshake(ServerHttpRequest request,
                               ServerHttpResponse response,
                               WebSocketHandler wsHandler,
                               Exception exception) {}
}
```

```java
@Component
@RequiredArgsConstructor

    public void afterConnectionEstablished(WebSocketSession session) {
        SESSIONS.add(session);
        log.info("WebSocket 连接建立 userId={}", session.getAttributes().get("userId"));
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        SESSIONS.remove(session);
        log.info("WebSocket 连接关闭 userId={}", session.getAttributes().get("userId"));
    }

    /**
     * 定时任务调用此方法推数据
     */
    public void broadcast(Object data) {
        String json = JSON.toJSONString(data);
        for (WebSocketSession session : SESSIONS) {
            try {
                if (session.isOpen()) {
                    session.sendMessage(new TextMessage(json));
                }
            } catch (IOException e) {
                log.error("推送失败 sessionId={}", session.getId(), e);
            }
        }
    }
}
```

### 9.12 智能补货算法详解

#### 9.12.1 核心公式

```
日均销量(avgDaily)    = Σ(最近N天销量) / N
可售库存(currentStock) = Σ(sto_stock.quantity - sto_stock.locked_quantity)
可维持天数(daysLeft)   = currentStock / avgDaily
安全库存(safetyStock)  = avgDaily × safetyDays
建议补货量(suggestQty) = max(0, (safetyStock + avgDaily × leadTime) - currentStock)
紧急度(urgency)        = daysLeft < 3 ? HIGH : daysLeft < safetyDays ? MEDIUM : LOW
```

#### 9.12.2 完整 SQL（单语句生成所有建议）

```sql
WITH
-- 最近 N 天每个 SKU 的日均销量
sales_avg AS (
    SELECT oi.sku_id,
           COALESCE(SUM(oi.quantity)::numeric / 30, 0) AS avg_daily
    FROM ord_order_item oi
    JOIN ord_order o ON oi.order_id = o.id
    WHERE o.pay_time >= NOW() - INTERVAL '30 day'
      AND o.status IN (1, 2, 3)   -- 已支付/已发货/已完成
    GROUP BY oi.sku_id
),
-- 当前可用库存
current_stock AS (
    SELECT sku_id,
           SUM(quantity - locked_quantity) AS available
    FROM sto_stock
    WHERE deleted = 0
    GROUP BY sku_id
)
INSERT INTO res_restock_suggestion
    (sku_id, current_stock, safety_stock, avg_daily_sales,
     days_remaining, suggested_quantity, urgency, reason, create_time)
SELECT
    s.sku_id,
    COALESCE(c.available, 0)                                                       AS current_stock,
    s.avg_daily * 7                                                                 AS safety_stock,
    s.avg_daily                                                                     AS avg_daily_sales,
    CASE WHEN s.avg_daily = 0 THEN 999
         ELSE COALESCE(c.available, 0) / s.avg_daily END                           AS days_remaining,
    GREATEST(0,
        (s.avg_daily * 7 + s.avg_daily * 3) - COALESCE(c.available, 0)
    )::int                                                                          AS suggested_quantity,
    CASE
        WHEN COALESCE(c.available, 0) / NULLIF(s.avg_daily, 0) < 3 THEN 'HIGH'
        WHEN COALESCE(c.available, 0) / NULLIF(s.avg_daily, 0) < 7 THEN 'MEDIUM'
        ELSE 'LOW'
    END                                                                             AS urgency,
    CONCAT('日均销量', ROUND(s.avg_daily, 2), '件，当前库存仅够维持',
           ROUND(COALESCE(c.available, 0) / NULLIF(s.avg_daily, 0), 1), '天')        AS reason,
    NOW()
FROM sales_avg s
LEFT JOIN current_stock c ON s.sku_id = c.sku_id
WHERE s.avg_daily > 0
ON CONFLICT (sku_id) DO UPDATE SET
    current_stock       = EXCLUDED.current_stock,
    safety_stock        = EXCLUDED.safety_stock,
    avg_daily_sales     = EXCLUDED.avg_daily_sales,
    days_remaining      = EXCLUDED.days_remaining,
    suggested_quantity  = EXCLUDED.suggested_quantity,
    urgency             = EXCLUDED.urgency,
    reason              = EXCLUDED.reason,
    create_time         = NOW();
```

#### 9.13.2 自定义注解 + AOP

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface OwnerCheck {
```

```java
@Aspect
@Component
@RequiredArgsConstructor
public class OwnerCheckAspect {

    private final OwnerWarehouseMapper ownerWarehouseMapper;

    @Before("@annotation(ownerCheck)")
    public void check(JoinPoint jp, OwnerCheck ownerCheck) {
        Object[] args = jp.getArgs();
        Map<String, Object> params = new HashMap<>();
        MethodSignature sig = (MethodSignature) jp.getSignature();
        String[] names = sig.getParameterNames();
        for (int i = 0; i < names.length; i++) params.put(names[i], args[i]);

        Long ownerId = (Long) params.get(ownerCheck.ownerIdParam());
        Long warehouseId = (Long) params.get(ownerCheck.warehouseIdParam());

        Integer count = ownerWarehouseMapper.countByOwnerAndWarehouse(ownerId, warehouseId);
        if (count == null || count == 0) {
            throw new BusinessException("货主无权操作该仓库", 403);
        }
    }
}
```

### 9.14 幂等设计指南（MQ + HTTP 通用）

#### 9.14.1 幂等三要素

| 要素 | 说明 |
|------|------|
| **唯一键** | 业务侧生成的唯一标识（UUID / 业务单号 / messageId） |
| **存储** | Redis SETNX（短期）/ MySQL 唯一索引（长期） |
| **结果缓存** | 第一次响应缓存一定时间，重复请求直接返回 |

#### 9.14.2 Redis 幂等模板

```java
public <T> T executeIdempotent(String idempotencyKey,
                               Supplier<T> action,
                               Duration cacheTime) {
    // 1. 抢占
    Boolean firstTime = redis.opsForValue()
        .setIfAbsent("idempotency:" + idempotencyKey, "1", Duration.ofSeconds(30));
    if (!Boolean.TRUE.equals(firstTime)) {
        // 2. 已存在 → 返回缓存结果
        Object cached = redis.opsForValue().get("idempotency:result:" + idempotencyKey);
        if (cached != null) return (T) cached;
        throw new BusinessException("请勿重复提交", 400);
    }

    try {
        // 3. 执行
        T result = action.get();

        // 4. 缓存结果
        redis.opsForValue().set("idempotency:result:" + idempotencyKey, result, cacheTime);
        return result;
    } catch (Exception e) {
        // 5. 失败释放锁
        redis.delete("idempotency:" + idempotencyKey);
        throw e;
    }
}
```

#### 9.15.1 Redis Lua 必测场景

| 场景 | 期望 |
|------|------|
| ✅ 库存充足扣减 | 返回 {1, remain}, Redis 库存 -qty |

| ⚠️ TTL 过期后 confirm | 返回 LOCK_NOT_FOUND，不报错 |

|------|------|

| ❌ 业务异常 | 抛异常 → 重试 3 次 → 入 DLQ |
