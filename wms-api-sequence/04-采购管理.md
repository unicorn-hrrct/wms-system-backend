## 4. 采购管理（第八章）— 完整状态机

### 4.0 状态流转全景

```
┌────────┐  submit  ┌──────────┐  audit_pass  ┌──────────┐  inbound_partial ┌──────────┐
│ 草稿/无 │ ───────▶ │ 待审核 0 │ ───────────▶ │ 待执行 0 │ ──────────────▶ │ 部分入库1 │
└────────┘          └──────────┘               └──────────┘                  └──────────┘
                          │                            │                            │
                       audit_reject                inbound_full               inbound_full
                          ▼                            ▼                            ▼
                     ┌──────────┐                ┌──────────┐                ┌──────────┐
                     │ 已驳回 2 │                │ 已完成 2 │                │ 已完成 2 │
                     └──────────┘                └──────────┘                └──────────┘
                          │                            │
                       (管理员撤回)               退货流程
                          ▼                            ▼
                     (回到草稿态)              ┌──────────┐

```

### 4.1 场景：提交采购申请

```
Client → POST /api/purchase/request {supplierId, items:[], remark}
       → PurchaseController → PurchaseRequestService
       │
       ├─ ① 生成 requestNo = "PO" + yyyyMMdd + 4位序号
       ├─ ② @Transactional
       │    ├─ 校验 supplierId 存在
       │    ├─ 遍历 items：
       │    │    ├─ 校验 skuId 存在
       │    │    ├─ 累加 total_amount = sum(expectedPrice * quantity)
       │    │    └─ INSERT pur_request_item
       │    ├─ INSERT pur_request（status=0 待审核）
       │    └─ 提交
       └─ ③ 返回 {requestId, requestNo, status:0}
```

### 4.2 场景：审核采购申请

```
Client → PUT /api/purchase/request/{id}/audit {auditStatus:1|2, auditRemark}
       → PurchaseRequestService
       │
       ├─ ① 校验当前 status=0
       ├─ ② UPDATE pur_request
       │       SET status=?, audit_remark=?, auditor=currentUser, audit_time=NOW()
       │     WHERE id=?
       └─ ③ 驳回则终止；通过则保持 status=1 等下一步生成采购订单
```

**异常分支**：status≠0 → `400 该申请已审核`。

### 4.3 场景：审核通过 → 生成采购订单

```
Client → POST /api/purchase/order {requestId, deliveryDate}
       → PurchaseOrderService
       │
       ├─ ① 校验 pur_request.status=1 且未生成过订单
       ├─ ② 复制 request.items 为 order.items
       ├─ ③ @Transactional
       │    ├─ 生成 orderNo
       │    ├─ INSERT pur_order（status=0 待执行）
       │    └─ 提交
       └─ ④ 返回 {orderId, orderNo, totalAmount, status:0}
```

### 4.4 场景：采购入库（核心，串联到库存）

```
Client → POST /api/purchase/inbound {orderId, warehouseId, items:[{orderItemId, skuId, actualQuantity, locationId, batchNo}]}
       → PurchaseInboundService
       │
       ├─ ① 校验 pur_order.status IN (0,1)
       ├─ ② @Transactional
       │    ├─ 遍历 items：
       │    │    ├─ 校验 orderItemId.skuId 与 items.skuId 一致
       │    │    ├─ UPSERT sto_stock
       │    │    │    INSERT ... ON CONFLICT (sku_id, warehouse_id, location_id)
       │    │    │    DO UPDATE SET quantity = quantity + ?
       │    │    ├─ 累加 actual_quantity 到 pur_request_item
       │    │    └─ INSERT sto_stock_log（type=1, source_no=orderNo, after_qty）
       │    ├─ 重新统计 pur_order 实际入库总额
       │    ├─ UPDATE pur_order SET status=
       │    │       CASE WHEN all_in THEN 2 ELSE 1 END
       │    └─ 提交
       └─ ⑤ 返回 {inboundId, inboundNo, status}
```

**状态变化**：`sto_stock.quantity` 累加；`sto_stock_log` 写流水（关键追溯点）；`pur_order.status` 推进。

**并发要点**：
- 入库是**累加**操作，必须用 `quantity + EXCLUDED.quantity` 而非 `SET quantity=?`
- 同一 SKU 同一库位的并发入库：`UNIQUE(sku_id, warehouse_id, location_id)` + `INSERT...ON CONFLICT` 保证原子
- 流水和库存变更必须在**同一事务**里

### 4.5 场景：采购退货

```
Client → POST /api/purchase/return {orderId, reason, items:[{skuId, quantity}]}
       → PurchaseReturnService
       │
       ├─ ① 校验退货数量 ≤ 已入库数量
       ├─ ② @Transactional
       │    ├─ UPDATE sto_stock SET quantity = quantity - ? WHERE sku_id=? AND warehouse_id=?
       │    ├─ INSERT sto_stock_log（type=2, quantity_change = -退货数）
       │    ├─ 若 stock.quantity 减到 0 → DELETE 或保留（推荐保留，quantity=0）
       │    └─ 若所有明细退货完成 → UPDATE pur_order.status=3
       └─ ③ 返回成功
```

**异常分支**：库存不足（被其他业务占用） → `50001 库存不足`。

### 4.6 接口路径速查（第八章）

| 接口 | 关键状态变化 |
|------|---------------|
| `GET  /api/purchase/request/list` | 只读 |
| `POST /api/purchase/request` | pur_request.status=0 |
| `PUT  /api/purchase/request/{id}/audit` | status: 0→1 或 0→2 |
| `POST /api/purchase/order` | pur_order.status=0 |
| `POST /api/purchase/inbound` | sto_stock+ + 流水 + pur_order 推进 |
| `POST /api/purchase/return` | sto_stock- + 流水 + 可能 pur_order.status=3 |
