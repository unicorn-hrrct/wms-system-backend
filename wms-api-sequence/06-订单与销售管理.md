## 6. 订单与销售管理（第十章）— 销售闭环

### 6.0 订单状态机（核心）

```
                ┌───── 取消 ◀────┐
                ▼                │
   ┌─────────┐ 支付  ┌─────────┐ 发货 ┌─────────┐ 收货 ┌─────────┐
   │ 待支付 0 │─────▶│ 已支付 1 │────▶│ 已发货 2 │────▶│ 已完成 3 │
   └─────────┘       └─────────┘      └─────────┘      └─────────┘
        │  超时/取消      │  取消(退款)     │  申请售后
        ▼                 ▼                ▼
   ┌─────────┐       ┌─────────┐       ┌─────────┐
   │ 已取消 4 │       │ 退款中  │       │ 售后中 5 │
   └─────────┘       └─────────┘       └─────────┘
```

#### 6.0.1 状态转换矩阵（开发必查）

| 操作 \ 当前状态 | 0 待支付 | 1 已支付 | 2 已发货 | 3 已完成 | 4 已取消 | 5 售后中 |
|-----------------|----------|----------|----------|----------|----------|----------|
| **支付** | ✅ → 1 | ❌ 50003 | ❌ 50003 | ❌ 50003 | ❌ 50003 | ❌ 50003 |
| **取消** | ✅ → 4 | ✅ → 4（走退款） | ❌ 50003 | ❌ | ❌ | ❌ |
| **发货** | ❌ 50003 | ✅ → 2 | ❌ | ❌ | ❌ | ❌ |
| **收货** | ❌ 50003 | ❌ 50003 | ✅ → 3 | ❌ | ❌ | ❌ |
| **申请售后** | ❌ 50003 | ❌ 50003 | ✅ → 5（订单项级） | ❌ | ❌ | ❌ |
| **超时自动取消** | ✅ → 4 | ❌ | ❌ | ❌ | ❌ | ❌ |

> 状态判断一律走 `WHERE id=? AND status=?`，影响行数=0 即视为非法状态变更，返回 `50003`。

### 6.1 场景：加入购物车

```
Client → POST /api/cart/add {skuId, quantity}
       → CartController → CartService
       │
       ├─ ① 校验 skuId 存在（SELECT 1 FROM pro_sku WHERE id=? AND deleted=0）
       ├─ ② UPSERT ord_cart（PG 写法）
       │    INSERT INTO ord_cart (user_id, sku_id, quantity, selected, create_time, update_time)
       │    VALUES (?, ?, ?, true, NOW(), NOW())
       │    ON CONFLICT (user_id, sku_id)
       │    DO UPDATE SET quantity = ord_cart.quantity + EXCLUDED.quantity,
       │                  update_time = NOW()
       └─ ③ 返回
```

**关键 SQL（完整可执行）**：

```sql
-- PostgreSQL 18
INSERT INTO ord_cart (user_id, sku_id, quantity, selected, create_time, update_time)
VALUES (#{currentUserId}, #{skuId}, #{quantity}, TRUE, NOW(), NOW())
ON CONFLICT (user_id, sku_id)
DO UPDATE SET
    quantity    = ord_cart.quantity + EXCLUDED.quantity,
    update_time = NOW()
RETURNING id, quantity;
```

**并发要点**：
- 同一用户重复点"加入购物车"必须用 `quantity + ?` 而非 `SET quantity=?`，否则覆盖会丢数量
- 如果想"重复点击合并为最新数量"（覆盖式），用 `DO UPDATE SET quantity = EXCLUDED.quantity`，但要前端确认交互
- **不加行锁**：UPSERT 的 `ON CONFLICT` 已经原子

**异常分支**：
- skuId 不存在 → `404 商品不存在`
- quantity < 1 → `400 数量必须≥1`

### 6.2 场景：下单（最复杂，串联：购物车→库存锁→订单→购物车清理）

```
Client → POST /api/order/create {addressId, cartItemIds:[], remark, couponId?}
       → OrderController → OrderService.create()
       │
       ├─ ① 加载 cartItemIds 对应的购物车项（校验都属于当前 user）
       │    SELECT c.*, s.price, s.sku_code, p.product_name, p.main_image
       │    FROM ord_cart c
       │    JOIN pro_sku s ON c.sku_id = s.id
       │    JOIN pro_product p ON s.product_id = p.id
       │    WHERE c.id IN (#{cartItemIds}) AND c.user_id = #{currentUserId}
       │    FOR UPDATE                          -- 锁购物车行，防并发下单
       │
       ├─ ② 加载 addressId 校验属于当前 user
       │    SELECT 1 FROM ord_address WHERE id=? AND user_id=? AND deleted=0
       │
       ├─ ③ 加载 sku + 实时计算 price（小计、优惠、运费）
       │    totalAmount = Σ(cartItem.quantity × sku.price)
       │    discountAmount = (启用 coupon) coupon.discount
       │    freight = (totalAmount ≥ 99) ? 0 : 10
       │    payAmount = totalAmount - discountAmount + freight
       │
       ├─ ④ 若启用 Redis 锁（13.1）：
       │    for each cartItem:
       │        POST /api/advanced/stock/lock/decrease
       │        {skuId, quantity, orderId: tempId, expireSeconds: 900}
       │        → 拿到 lockId
       │        → 任一失败 → 释放已成功的锁 → 抛 50001
       │
       ├─ ⑤ @Transactional(rollbackFor = Exception.class)
       │    ├─ 扣减库存（DB 层，最终防线）
       │    │    UPDATE sto_stock
       │    │    SET quantity          = quantity - #{qty},
       │    │        locked_quantity   = locked_quantity + #{qty},
       │    │        update_time       = NOW()
       │    │    WHERE sku_id = #{skuId}
       │    │      AND warehouse_id = #{defaultWarehouseId}   -- 或 SELECT 选最优仓库
       │    │      AND (quantity - locked_quantity) >= #{qty}  -- 条件更新，无锁原子
       │    │    -- 影响行数=0 → 抛 50001 → 释放 Redis 锁 → 事务回滚
       │    │
       │    ├─ INSERT ord_order
       │    │    (order_no, user_id, status=0, total_amount, pay_amount, freight,
       │    │     discount_amount, address_id, remark, expire_time=NOW()+30min, ...)
       │    │
       │    ├─ 遍历 items：INSERT ord_order_item
       │    │    (order_id, sku_id, sku_code, product_name, spec_values(JSONB),
       │    │     price, quantity, subtotal, main_image)
       │    │
       │    ├─ DELETE FROM ord_cart WHERE id IN (#{cartItemIds}) AND user_id=?
       │    │
       │    ├─ 遍历 items：INSERT sto_stock_log
       │    │    (sku_id, sku_code, type=2, type_name='订单预扣',
       │    │     quantity_change=-qty, before_qty, after_qty,
       │    │     source_no=orderNo, operator=currentUsername)
       │    │
       │    └─ 提交事务
       │
       ├─ ⑥ 本地消息表 INSERT（保证 MQ 不丢）
       │    INSERT INTO local_message
       │    (message_id=UUID, topic='order.created', payload=JSON,
       │     status=0待发送, retry_count=0)
       │    -- @Transactional 与上面一起提交
       │
       ├─ ⑦ 事务提交后异步投递（Spring Transactional Event / ScheduledJob）
       │    MQProducer.send(order.created, payload) → ack=1成功
       │    UPDATE local_message SET status=1已发送 WHERE message_id=?
       │
       └─ ⑧ 返回 {orderId, orderNo, totalAmount, payAmount, expireTime}
```

**关键并发控制三层**：

| 层级 | 机制 | 失败处理 |
|------|------|----------|
| **第 1 层 Redis Lua** | 快速失败，不进 DB | 抛 50001，不影响后续 |
| **第 2 层 DB 条件更新** | `WHERE (quantity-locked_quantity) >= ?`，影响行数校验 | 影响行数=0 → 抛 50001，回滚事务 |
| **第 3 层 行级锁**（兜底） | `SELECT ... FOR UPDATE` 锁住 sto_stock 行 | 锁等待超时 → 重试或降级 |

**异常分支**：
- `50001 库存不足` → 释放 Redis 锁（cancel action）→ 提示用户
- `50002 库存扣减失败（并发冲突）` → 重试 3 次后提示
- 优惠券失效 → 回滚事务，不创建订单
- 地址已被删除 → 回滚事务

### 6.3 场景：订单支付

```
Client → POST /api/order/{id}/pay {payType:1|2|3, payPassword?}
       → OrderService.pay()
       │
       ├─ ① 校验订单存在 + 归属当前 user
       │    SELECT * FROM ord_order WHERE id=? AND user_id=? AND deleted=0 FOR UPDATE
       │
       ├─ ② 校验状态合法：order.status == 0（待支付）
       │    WHERE id=? AND status=0  -- 影响行数=0 → 50003
       │
       ├─ ③ 校验未过期：order.expire_time > NOW()，否则走取消逻辑
       │
       ├─ ④ 校验 payType
       │    payType=1（支付宝）→ 构造支付链接，二维码
       │    payType=2（微信）   → 构造支付链接，二维码
       │    payType=3（余额）   → BCrypt.matches(payPassword, user.pay_password)
       │
       ├─ ⑤ 余额支付：原子扣减（防并发扣款）
       │    UPDATE sys_user SET balance = balance - #{payAmount}
       │    WHERE id=? AND balance >= #{payAmount}  -- 影响行数=0 → 余额不足
       │
       ├─ ⑥ @Transactional
       │    ├─ 第三方/余额扣款完成
       │    ├─ UPDATE ord_order
       │    │    SET status=1, pay_time=NOW(), pay_type=#{payType}, pay_amount=#{payAmount}
       │    │    WHERE id=? AND status=0  -- 二次校验
       │    │
       │    ├─ Redis 锁 confirm（13.1）：locked_quantity 真扣减，移除 lockKey
       │    │    实际上 quantity 没变（预扣时已减），只减 locked_quantity
       │    │
       │    ├─ INSERT pay_log（如果表存在）
       │    │    (order_id, pay_no='PAY'+yyyyMMdd+序号, pay_type, pay_amount, status=1)
       │    │
       │    └─ INSERT local_message (topic='order.paid', payload=...)
       │
       ├─ ⑦ 事务提交后：异步发 MQ → 物流服务、积分服务
       │
       └─ ⑧ 返回 {payNo, payStatus:1, payTime}
```

**过期支付处理（定时任务）**：

```java
@Scheduled(fixedRate = 60_000)  // 每分钟跑一次
public void cancelExpiredOrders() {
    List<Long> ids = orderMapper.selectExpiredIds(); // status=0 AND expire_time<NOW()
    for (Long id : ids) {
        try {
            orderService.cancelInternal(id, "系统：支付超时自动取消");
        } catch (Exception e) {
            log.error("自动取消订单失败 id={}", id, e);
        }
    }
}
```

**异常分支**：
- 余额不足 → `400 余额不足`
- 支付密码错 → `400 支付密码错误`
- 订单已支付 → `50003 订单状态异常`
- 订单已过期 → `400 订单已过期，请重新下单`

### 6.4 场景：取消订单（双路径）

```
Client → PUT /api/order/{id}/cancel {cancelReason}
       → OrderService.cancel()
       │
       ├─ ① SELECT * FROM ord_order WHERE id=? AND user_id=? FOR UPDATE
       │
       ├─ ② 校验 status IN (0, 1) -- 只有这两个状态允许取消
       │    校验不通过 → 50003
       │
       ├─ ③ @Transactional
       │    │
       │    ├─ 若 status=0（待支付）：
       │    │    ├─ UPDATE ord_order
       │    │    │    SET status=4, cancel_reason=?, cancel_time=NOW()
       │    │    │    WHERE id=? AND status=0  -- 二次校验
       │    │    │
       │    │    ├─ 释放预扣库存：UPDATE sto_stock
       │    │    │    SET locked_quantity = locked_quantity - #{qty}
       │    │    │    WHERE sku_id=? AND warehouse_id=?
       │    │    │
       │    │    ├─ Redis 锁 release action=cancel（不增加 quantity）
       │    │    │
       │    │    └─ INSERT local_message (topic='order.cancelled', payload)
       │    │
       │    └─ 若 status=1（已支付未发货）：
       │         ├─ UPDATE ord_order
       │         │    SET status=4, cancel_reason=?, cancel_time=NOW()
       │         │    WHERE id=? AND status=1  -- 二次校验
       │         │
       │         ├─ 释放库存 + 写流水：UPDATE sto_stock
       │         │    SET quantity        = quantity + #{qty},
       │         │        locked_quantity = locked_quantity - #{qty}
       │         │    WHERE sku_id=? AND warehouse_id=?
       │         │
       │         ├─ INSERT sto_stock_log（type=2, quantity_change=+qty, remark='订单取消回滚'）
       │         │
       │         ├─ INSERT refund_request（异步走退款流程）
       │         │    status=0待退款, order_id, amount, reason
       │         │
       │         ├─ 若余额支付：UPDATE sys_user SET balance = balance + #{payAmount}
       │         │
       │         └─ INSERT local_message (topic='order.cancelled', payload)
       │
       └─ ④ 返回
```

**关键差异表**：

| 维度 | status=0 取消 | status=1 取消（已支付） |
|------|---------------|-------------------------|
| 库存操作 | 只减 locked_quantity | quantity+locked_quantity 一起回滚 |
| Redis 锁 | release cancel | release cancel |
| 退款 | 无 | 走第三方退款 / 余额返还 |
| 流水 | 不写（无实际库存变化） | 写一条 quantity_change=+qty 的入库流水（取消入账） |
| MQ | order.cancelled | order.cancelled + refund.initiated |

**异常分支**：
- 订单已发货 → `50003 已发货订单不能取消，请走售后`

### 6.8 事务边界图

```
┌──────────────────────────────────────────────────────────────────────┐
│                       @Transactional 边界                              │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   OrderService.create()                                               │
│   ┌──────────────────────────────────────────────────────────────┐   │
│   │ @Transactional(rollbackFor=Exception.class)                  │   │
│   │                                                              │   │
│   │   ① 锁购物车 FOR UPDATE                                      │   │
│   │   ② 加载地址                                                 │   │
│   │   ③ 加载 SKU 价格（不在事务内也行，单独 SELECT）              │   │
│   │   ④ Redis 锁（不在事务内，事务外调用）                       │   │
│   │   ┌──────────────────────────────────────────────────────┐  │   │
│   │   │ ⑤ DB 扣库存 UPDATE sto_stock  WHERE (quantity-locked) │  │   │
│   │   │     → 影响行数=0 → 抛 50001 → 整体回滚                 │  │   │
│   │   │ ⑥ INSERT ord_order                                    │  │   │
│   │   │ ⑦ INSERT ord_order_item × N                           │  │   │
│   │   │ ⑧ DELETE ord_cart                                     │  │   │
│   │   │ ⑨ INSERT sto_stock_log × N                            │  │   │
│   │   │ ⑩ INSERT local_message                                │  │   │
│   │   └──────────────────────────────────────────────────────┘  │   │
│   │                                                              │   │
│   └──────────────────────────────────────────────────────────────┘   │
│       │                                                              │
│       ▼                                                              │
│   事务提交后才执行：                                                   │
│       ├─ Spring TransactionalEventListener → 投递 MQ                  │
│       └─ ScheduledJob 扫描 local_message.status=0 重投                  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**关键原则**：
1. **DB 操作尽量在同一个 `@Transactional`**：要么全成功要么全回滚
2. **Redis 锁在事务外调用**：Redis 不是事务资源
3. **MQ 在事务提交后异步发**：用 Spring `@TransactionalEventListener(phase = AFTER_COMMIT)` 或本地消息表
4. **外层调用方捕获异常后释放 Redis 锁**

### 6.9 关键 SQL 脚本集

#### 6.9.1 下单核心 SQL（MyBatis-Plus 写法）

```java
// Mapper.java
public interface OrderMapper extends BaseMapper<Order> {

    /**
     * 扣减库存（条件更新 + 影响行数校验）
     * @return 1=成功，0=库存不足
     */
    @Update("""
        UPDATE sto_stock
        SET quantity        = quantity - #{qty},
            locked_quantity = locked_quantity + #{qty},
            update_time     = NOW()
        WHERE sku_id       = #{skuId}
          AND warehouse_id = #{warehouseId}
          AND (quantity - locked_quantity) >= #{qty}
        """)
    int decreaseStock(@Param("skuId") Long skuId,
                      @Param("warehouseId") Long warehouseId,
                      @Param("qty") Integer qty);
}
```

#### 6.9.4 释放库存（双路径合一）

```java
// 取消订单时根据原状态决定库存操作
@Update("""
    UPDATE sto_stock
    SET quantity        = quantity + CASE WHEN #{restoreQty} THEN #{qty} ELSE 0 END,
        locked_quantity = locked_quantity - #{qty},
        update_time     = NOW()
    WHERE sku_id       = #{skuId}
      AND warehouse_id = #{warehouseId}
    """)
```

### 6.10 幂等设计

#### 6.10.1 幂等键设计

| 接口 | 幂等键 | 用途 |
|------|--------|------|
| `POST /api/order/create` | `Idempotency-Key` Header（UUID） | 防止重复点击导致多单 |
| `POST /api/order/{id}/pay` | orderId + 同一 orderNo 只允许一次成功 | 防止重复支付 |
| `POST /api/order/{id}/cancel` | orderId | 重复请求返回原结果 |

#### 6.10.2 实现模式：Token 桶 + 状态机

```java
// 伪代码：下单幂等
public Result createOrder(IdempotentRequest req) {
    // 1. 客户端生成 UUID 作为幂等键，放入 Header
    String idempotencyKey = req.getHeader("Idempotency-Key");

    // 2. Redis SETNX 抢占，30 秒过期
    Boolean firstTime = redisTemplate.opsForValue()
        .setIfAbsent("idempotency:order:" + idempotencyKey, "1", 30, TimeUnit.SECONDS);
    if (!Boolean.TRUE.equals(firstTime)) {
        // 3. 已存在 → 查上次结果缓存
        Order cached = (Order) redisTemplate.opsForValue().get("idempotency:order:result:" + idempotencyKey);
        if (cached != null) return Result.success(cached);
        throw new BusinessException("请勿重复提交");
    }

    try {
        // 4. 正常下单
        Order order = orderService.create(req);

        // 5. 结果缓存 5 分钟
        redisTemplate.opsForValue().set(
            "idempotency:order:result:" + idempotencyKey, order, 5, TimeUnit.MINUTES);

        return Result.success(order);
    } catch (Exception e) {
        // 6. 失败释放幂等键，允许重试
        redisTemplate.delete("idempotency:order:" + idempotencyKey);
        throw e;
    }
}
```

#### 6.13.2 Service 层（核心：下单）

```java
@Service
@RequiredArgsConstructor
public class OrderServiceImpl extends ServiceImpl<OrderMapper, Order> implements OrderService {

    private final CartMapper cartMapper;
    private final SkuMapper skuMapper;
    private final StockMapper stockMapper;
    private final StockLogMapper stockLogMapper;
    private final AddressMapper addressMapper;
    private final LocalMessageMapper localMessageMapper;
    private final StockLockService stockLockService;       // 13.1 Redis 锁

    @Override
    @Transactional(rollbackFor = Exception.class)
    public Order create(OrderCreateDTO dto, String idempotencyKey) {

        // ① 幂等检查（Redis SETNX）

        // ② 加载购物车 + 校验归属
        List<CartItem> items = cartMapper.selectByIdsAndUser(dto.getCartItemIds(), SecurityUtil.currentUserId());
        if (items.isEmpty()) throw new BusinessException("购物车项无效");

        // ③ 加载地址
        Address addr = addressMapper.selectByIdAndUser(dto.getAddressId(), SecurityUtil.currentUserId());
        if (addr == null) throw new BusinessException("收货地址无效");

        // ④ 计算金额
        BigDecimal total = items.stream()
            .map(i -> i.getPrice().multiply(BigDecimal.valueOf(i.getQuantity())))
            .reduce(BigDecimal.ZERO, BigDecimal::add);

        // ⑤ Redis 锁（事务外调用，但失败抛异常触发外层 catch 释放）
        List<Long> lockIds = new ArrayList<>();
        try {
            for (CartItem item : items) {
                String lockId = stockLockService.lockDecrease(
                    item.getSkuId(), item.getQuantity(), null, 900);
                lockIds.add(Long.parseLong(lockId.split("-")[1]));
            }
        } catch (BusinessException e) {
            // 已成功的锁释放
            lockIds.forEach(id -> stockLockService.release(id, "cancel"));
            throw e;
        }

        // ⑥ 创建订单
        Order order = new Order();
        order.setOrderNo(generateOrderNo());
        order.setUserId(SecurityUtil.currentUserId());
        order.setStatus(0);
        order.setTotalAmount(total);
        order.setPayAmount(total.subtract(BigDecimal.valueOf(dto.getDiscount() != null ? dto.getDiscount() : 0)));
        order.setAddressId(addr.getId());
        order.setReceiverName(addr.getReceiverName());
        order.setReceiverPhone(addr.getReceiverPhone());
        order.setReceiverAddr(buildFullAddress(addr));
        order.setExpireTime(LocalDateTime.now().plusMinutes(30));
        save(order);

        // ⑦ DB 层扣库存（最终防线）
        for (CartItem item : items) {
            int affected = stockMapper.decreaseStock(
                item.getSkuId(),
                getDefaultWarehouseId(),
                item.getQuantity()
            );
            if (affected == 0) {
                throw new BusinessException("库存不足", 50001);
            }
        }

        // ⑧ 写订单项
        for (CartItem item : items) {
            OrderItem oi = new OrderItem();
            oi.setOrderId(order.getId());
            oi.setSkuId(item.getSkuId());
            oi.setQuantity(item.getQuantity());
            oi.setPrice(item.getPrice());
            oi.setSubtotal(item.getPrice().multiply(BigDecimal.valueOf(item.getQuantity())));
            orderItemMapper.insert(oi);
        }

        // ⑨ 清空购物车
        cartMapper.deleteByIds(dto.getCartItemIds());

        // ⑩ 写库存流水
        items.forEach(item ->
            stockLogMapper.insert(buildLog(item.getSkuId(), -item.getQuantity(), "订单预扣", order.getOrderNo()))
        );

        // ⑪ 本地消息表（MQ 发送）
        LocalMessage msg = new LocalMessage();
        msg.setMessageId(UUID.randomUUID().toString());
        msg.setTopic("order.created");
        msg.setPayload(JSON.toJSONString(order));
        msg.setStatus(0);
        localMessageMapper.insert(msg);

        // ⑫ 触发 MQ 投递（事务后）
        TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
            @Override
            public void afterCommit() {
                mqProducer.send("order.created", msg.getMessageId(), msg.getPayload());
            }
        });

        return order;
    }
}
```

### 6.14 关键设计回顾

| 设计点 | 实现机制 | 失败后果 |
|--------|----------|----------|
| **防超卖 3 层防御** | Redis Lua + DB 条件更新 + 行级锁 | 任一层失败 → 抛 50001 |
| **MQ 不丢** | 本地消息表 + 事务后投递 + 定时重投 | MQ 宕机也不丢消息 |
| **幂等防重** | Idempotency-Key + Redis SETNX | 重复请求返回原结果 |
| **状态一致性** | 状态机校验矩阵 + 双重 WHERE | 非法状态变更返回 50003 |
| **库存一致性** | 库存变更 + 流水同事务 | 不一致自动回滚 |
| **过期处理** | @Scheduled 每分钟扫描 | 超时订单自动取消 |
