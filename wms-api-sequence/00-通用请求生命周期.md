## 0. 通用：每个请求的生命周期

任何业务接口都必须经历的下图链路，先理解这张图，后面的时序图都是它的细化。

```
┌────────┐   HTTP       ┌──────────────────┐
│ Client │ ───────────▶ │ SecurityFilterChain │
└────────┘              │  (Spring Security 7) │
                        └──────────┬───────────┘
                                   │ 1. CORS 预检放行
                                   │ 2. /api/auth/** 与 /api/shop/** permitAll 放行
                                   │ 3. 其余进入 JwtAuthenticationFilter
                                   ▼
                        ┌──────────────────────────┐
                        │ JwtAuthenticationFilter  │
                        │  ① extractToken(req)     │
                        │  ② jwtUtil.validateToken │
                        │  ③ 解析 userId/username  │
                        │  ④ loadUserByUsername    │
                        │  ⑤ SecurityContextHolder │
                        │     .setAuthentication() │
                        └──────────┬───────────────┘
                                   ▼
                        ┌──────────────────────────┐
                        │ Controller（@RestController）│
                        │  ① 参数校验 @Valid         │
                        │  ② 调用 *Service           │

                        ┌──────────────────────────┐
```

### 0.1 JWT 鉴权失败矩阵

| Token 状态 | 行为 | HTTP | 业务码 |
|------------|------|------|--------|
| 无 `Authorization` 头 | SecurityContext 为空 → 拒绝 | 401 | 401 |
| 头格式错（不是 `Bearer xxx`） | `extractToken` 返回 null | 401 | 401 |
| 签名错误 / 已过期 / 被篡改 | `validateToken` 返回 false | 401 | 401 |
| Token 合法但用户 `status=1` 禁用 | 仍能进 Controller，但业务层抛 | 200 | 500 / 自定义 |
| `/api/auth/**`、`/api/shop/**` 公开路径 | 直接放行 | — | — |

### 0.2 通用分页/排序约定

- 所有列表接口统一接 `pageNo`（默认 1）/ `pageSize`（默认 10）
- MP 分页插件（`POSTGRE_SQL` 方言）自动生成 `LIMIT ? OFFSET ?`
- 业务层返回 `PageResult<T>`：`{ total, pageNo, pageSize, pages, list }`
